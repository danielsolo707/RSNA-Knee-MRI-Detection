## 1) Can we fine-tune the 0.936 model? — YES, and it is the main lever

V33 is **not one model**. It is a rank fusion of:

- **Transformer branch** — DINOv2-small, 20-member weighted rank mean (~0.920)
- **CoAtNet branch** — `raptor_ft_coatnet_v5_full_swa.pt` primary (the 0.935 "MaxSpan")
  + `raptor_ft_coatnet_v4_full.pt` complement on the 2nd T4

The trainable piece is the CoAtNet branch, and the key discovery of today's audit:

> `raptor_ft_coatnet_v5_full_swa.pt` saves as `{"model": state_dict, "arch": str,
> "res": int}` — **exactly** the dict format `tools/train_raptor.py --resume` expects
> (`model.load_state_dict(resume_ck["model"])`, reads `arch`, `res`).
> Verified against `load_model()` inside the V33 notebook, which does
> `model.load_state_dict(ck["model"], strict=True)`.

So we can initialise from the strong public checkpoint instead of ImageNet.
**V34/V35 burned ~9 h to get to gold 0.760 from ImageNet; this starts at gold ~0.917 —
roughly ten epochs of GPU obtained for free.**

Hosted at `dreaddevelopment/raptor-knee-maxspan` (292.8 MB, already attached to V33).

### Bonus: one public checkpoint is currently unused

`dreaddevelopment/raptor-knee-widedense` contains **two** files:

| file | used by V33? |
|---|---|
| `raptor_ft_coatnet_v4_full.pt` | yes — the complement arm |
| `raptor_ft_coatnet_v4_full_swa.pt` | **NO — never loaded** |

A third vote that costs zero training. Low expected value (SWA vs non-SWA of the same
run are correlated) but it is nearly free.

### What makes fine-tuning actually *better*, not just different

Fine-tuning on the same labels risks converging back to the same place. The lever that
can genuinely move it is **distillation**:

1. Run the **full 0.936 fusion** (transformer + CoAtNet) over the 4,349 training studies.
2. The fusion is stronger (0.936) than either arm alone (0.920 / 0.924), so its
   predictions are *better labels than the soft labels the arm was trained on*.
3. Fine-tune `v5_full_swa` on a blend of those pseudo-labels and the original soft labels.

This is the one idea in this plan that produces an arm the public pile cannot contain.

### Track A — exploit the incumbent · ~2 h GPU · 1 submit · do FIRST

V33's complement arm is muted: its weight table starts at 0.10–0.16 but the
`corr > 0.992 → ×0.50` damper cut it to **0.04–0.08** on the 3-study dry run.

- A1. Raise the complement table and/or relax the damper; **preserve per-arm CSVs**

- A2. Add `raptor_ft_coatnet_v4_full_swa.pt` as a third CoAtNet vote (§1).
- Gate: dry-run on the 3-study public test, confirm wiring is finite/valid.

Expected +0.000 … +0.003. Cheap enough that skipping it would be a mistake.

### Track B — fine-tune from the public checkpoint · ~8 h GPU · **built, ready to push**

`kaggle/ft_v36_public_init/` — V36. Differences from V35:

| | V35 (from ImageNet) | **V36 (from public ckpt)** |
|---|---|---|
| init | timm ImageNet | `raptor_ft_coatnet_v5_full_swa.pt` |
| start gold-58 | ~0.68 → 0.760 after 2 ep | **~0.917 at step 0** |
| LR | 3e-5 / 1e-3 | **1e-5 / 1e-4** (converged model) |
| k / epochs | 12 / 12 | **10 / 2** (fits the 9 h cap with margin) |
| guards | `--require_resume` | **`--require_resume` + `--eval_first`** |

`--eval_first` is **new** (added to `tools/train_raptor.py` today). It scores the public
checkpoint on gold-58 *before* training and adopts it as the baseline. Without it the
first epoch becomes "best" by default and the run is uninterpretable.

**Gate:** if gold-58 does not beat the printed baseline, stop — do not chain sessions.

### Track C — distillation (the real edge) · ~15 h GPU · week of 2026-09-05

- C1. Inference kernel: run the V33 fusion over the 4,349 **training** studies
  (corpus is on Kaggle; ~3–4 h). Save per-study, per-target predictions.
- C2. Offline: build pseudo-labels = blend(fusion preds, original soft labels).
  Validate on gold-58 with `tools/score_label_banks.py` first — **if the blend does not
  beat the current labels on gold-58, do not spend training on it.**
- C3. Fine-tune `v5_full_swa` on those labels, low LR, 3 epochs (~11 h at k=10).

### Track D — local decorrelated arm · 0 GPU quota · after the download

The 4070 has unlimited hours; the only cost is wall-clock and 8 GB VRAM.
Train a **deliberately different** arm (different backbone family / resolution /
windowing) so it is *decorrelated* from both public arms — fusion rewards
decorrelation, not solo score. Then:

- Upload the checkpoint (~293 MB; measured 0.10 MB/s ≈ 47 min — prefer a faster link).
- Attach as a private Kaggle dataset (**upload verified working today**).
- Inference kernel fuses local arm + V33.

**Not this:** re-training CoAtNet-384 locally on the public recipe. That recreates a
0.924 arm and wastes a week.

## 4) Decision gates (fail-closed at every step)

| gate | condition to proceed |
|---|---|
| A → submit | 3-arm fusion is finite/valid on dry-run; gold direction non-negative |
| B → chain more epochs | gold-58 **strictly beats** the `--eval_first` baseline |
| B → C | B gives ≥ +0.003 gold, or B shows fine-tuning responds at all |
| C2 → C3 | pseudo-label blend **beats** current labels on gold-58 |
| any arm → submission | offline rank-blend with `tools/blend_gold.py` beats 0.936-equivalent on gold-58 |

**Selection discipline:** the public LB has ~1,300 test studies and we get 5 submits/day.
Differences of ±0.001 are noise. Choose the two final submissions by **gold-58 + OOF
robustness**, not by public score alone. (`docs/strategy.md` says the same.)

## 4b) Survival machinery (the thing that makes long runs safe)

`tools/train_raptor.py` now carries:

| flag / behaviour | effect |
|---|---|
| `--max_wall_h 8.3` | stops **gracefully** (save + exit) before Kaggle's 9 h cap, so `/kaggle/working` is committed |
| `--ckpt_every_min` | resumable mid-epoch checkpoint + tiny `progress_<tag>.json`; a kill costs minutes, not a ~4 h epoch |
| mid-epoch resume | checkpoint stores `step`; the first resumed epoch uses `Subset(tds, range(mid_step, …))` so it continues *inside* the epoch |
| wallstop | if the budget hits mid-epoch, save then stop cleanly |
| epoch guard | won't start an epoch it can't finish (30 min reserve) |

**Recovery:** `python tools/pull_kernel_output.py <owner/slug> --small-only`
(cheap — json/npz/log only, prints progress) or drop the pattern to fetch the `.pt`.
Note: the sandbox proxy breaks `ListKernelSessionOutput`; the tool unsets it for you.

**Chaining:** the next session attaches the previous kernel via `kernel_sources` and the
trainer auto-discovers `raptor_ft_<tag>*.pt` under `/kaggle/input` — no download/upload
round-trip needed to continue.
